# 文件与交付规范

本规范只用于选项 1/2 的项目音色工作流。选项 3 内置生成按当前应用说明交付实际音频/链接，不强制创建本规范的 Job、分句、字幕或文档目录；用户明确要求本地整理时才复用适用的命名规则，不因此调用项目生成接口。

## 位置和命名

所有用户产物归当前项目，不写到 Skill 程序目录。默认使用 `配音/<任务名称>/`；用户明确指定已有目录时沿用。任务名从剧本标题或内容提炼为简短可读名称，同名的不同任务加编号区分，不覆盖原任务。清理文件名中的路径分隔符和 Windows 非法字符，不让用户文本成为任意路径。

```text
<当前项目>/
├─ 配音/
│  └─ 梦与潜意识/
│     ├─ 剧本.md
│     ├─ 配音演绎单_v01.md
│     ├─ 配音演绎单_v02.md
│     ├─ 交付说明.md
│     ├─ 文件索引.md
│     ├─ 试听/
│     │  └─ 第001组/S6_沈舟_精英青年_候选01.wav
│     ├─ v01_初版/
│     └─ v02_阿哲换声/
│        ├─ 合并试听_第001-005段.wav
│        ├─ 合并试听_第001-005段.srt
│        └─ 分句/
│           ├─ 001_小林.wav
│           ├─ 001_小林.srt
│           ├─ 002_阿哲.wav
│           └─ 002_阿哲.srt
└─ .makesound/
   ├─ workspace/<task-key>/inputs/  manifest、推荐、绑定、items、targets 等输入
   ├─ exports/audio/<job_id>/      运行时内部导出
   └─ 其余内部状态、绑定、计划、缓存和收据
```

使用原剧本的稳定段落编号，至少三位补零；全篇超过 999 段时统一增加位数。试听选了第 2、7、9 段，就保留 002、007、009，不能重新编号为 001、002、003。非连续范围的合并文件命名为 `角色试听_第002、007、009段.wav` 等，不能用连续范围误导。版本编号递增，名称说明变化；不要用 Job UUID、p_002 或“最终最终版”作为用户主要文件名。

## 格式和内容

- 剧本、演绎单和交付说明采用 UTF-8 Markdown。用户原始剧本文件保持不变；必要时生成可读副本，不把整理当作改写授权。
- 演绎单用中文角色名和绑定声音名，逐句展示实际参数。内部角色 ID、Job ID、计划哈希不放在正文开头；内部映射保存在 `.makesound`，需要排错时再引用。
- 默认音频 WAV，字幕同名 SRT；不为统一目录擅自重采样、改变声道或转为有损格式。额外 MP3 仅按用户需要本地导出。
- 分句音频保留完整语音及句内停顿，不截取、不限制十秒，不额外追加段间静音。若运行时源导出已有段后静音，仅根据可信的语音时长/导出元数据去除该追加部分，不能凭听感或猜测裁尾。
- 分句字幕从零计时；合并音频按原文顺序拼接，仅添加一次确认的段间停顿，合并字幕重算时间偏移。缺少真实字幕时明确标记未完成，不能编造时间或生成空字幕冒充成功。

## 版本和完成范围

每次修订只合成变化句子；新版本的 `分句/` 必须包含此次已完成范围内的全部可用片段和字幕，未修改的从已校验旧文件本地复制/复用，不再付费。用户拿一个版本目录即可剪辑，不必跨多个 Job 或 replacement-segments/original-segments 目录拼凑。

旧版音频、字幕、演绎单和收据一律保留。三个修订审核入口仍为：新合并音频、替换句、新版对应的旧句；旧句链接旧版本即可，不为提供入口重复建立含混的“原版”副本。

`交付说明.md` 明确列出当前可用版本及相对链接、对应演绎单、总段数、已完成段号、待生成或失败段号、修改内容和必要的格式/停顿说明。仅完成 6 段中的前 5 段时写“已完成第 001–005 段，第 006 段待生成”，不可标成全剧完成。首轮角色试听与完整对白交付也应明确区分。

后续批次可增补尚未占用的分句文件；生成新的合并范围文件并更新交付说明。任何已有文件若内容会改变，创建新版本，不覆盖旧交付。新合并或字幕失败时保留上一可用版本入口，并明确新版本尚未完成。

## 与现有运行时的衔接和验证

新运行时源导出统一为 `.makesound/exports/audio/<job_id>/`，不再新建公开的 `outputs/audio`。已有 `outputs/audio` 文件及引用仍兼容，不擅自移动或删除；`.makesound` 中冻结状态、缓存和收据也不移动。只把需要交付的文件本地复制到可读任务目录。项目根目录不放推荐、绑定、分批 items/targets、命令输出或临时脚本；先按通用接口准备工作目录，使用返回的 `inputs_dir`。不要将工具全部输出保存成用户文档或重复复制运行时已有计划。

### 正式交付入口（候选生成后不使用本入口冒充正式版本）

同一份完整 final-items 用于复用比较、正式生成和本地交付。完成所有范围后调用：

```text
python -X utf8 -m makesound.final_delivery publish --project "<project>" --question "<current-answered-question_id>" --items "<final-items.json>" --selection "<selection_id>" --job "<completed-job-id>" --task "<stable-task-key>" --title "<任务名称>" --version "v01_初版"
```

多个实际 Job 重复 `--job`；无推荐选声记录省略 `--selection`，全稿由已认可试听覆盖时可不传 Job。入口根据真实任务状态定位音频，检查原文、保存绑定、实际 provider_directives/inline_controls、哈希、时长及完整覆盖；错参、缺音频或多个不同来源争用同一句时拒绝，不猜缓存哈希、不重新生成。

它只导出已验证且格式匹配的单声道 PCM WAV，按可信 speech_seconds 保留完整供应商语音，去除生成器追加的段后静音；正式分句不再带这段静音，合并按 final-items 仅插入一次段间停顿。没有可信边界或格式不匹配时报告缺项，不猜测裁尾、不自动重采样。严禁 Agent 自写 wave 拼接或手抄缓存路径代替本入口。

入口生成完整版本的分句、合并音频、剧本、记录实际情绪/控制的演绎单、交付说明及内部来源映射，并自动更新文件索引。仅导出真正验证的字幕；有些缺失时保留已可用分句字幕，但不生成不完整的整稿 SRT。返回 audio_status、subtitle_status、index_status 等，字幕缺失为 audio_ready_subtitles_missing；不是全部任务完成。默认声音由单独默认入口保存，本工具返回 default_status=not_changed，不能据此宣称已设置。

同一版本和相同输入重复运行只核对并复用已有交付；输入不同、文件被用户修改或版本目录已存在但没有有效映射时拒绝覆盖。修订用新版本；原音频、旧版、冻结状态和收据保持不变。索引被用户修改时保留音频和版本，返回 index_status=needs_review，不覆盖索引；须单独报告该待办。

### 固定整理入口

候选试听生成后，直接用本地入口校验并建立用户副本，代替手写复制脚本或先读一遍 `audition_results`。它不生成音频、不下载字幕，不依赖字幕成功；同一 audition 重复执行复用同组及文件名，不覆盖变更过的交付文件。新试听自动分组，名称保留原句 ID、角色和候选名；来源映射保存内部。已有 `试听01` 等目录保留，不为统一命名复制一套。

```text
python -X utf8 -m makesound.project_files publish-audition --project "<project>" --task "<stable-task-key>" --title "<任务名称>" --audition "<audition_id>"
```

逐个展示返回的 `audio[].audio_path`；`partial` 只交付实际成功项。首次正式交付仍按本规范建立完整版本/分句及交付说明，本入口只负责候选试听，不把候选比较当正式成品。

增加正式文件或整理已有目录后，可更新自动文件索引；索引只列实际文件和 WAV 时长，不判定任务完成，也不替代交付说明。索引被用户修改时停止覆盖；其余文档和音频保持原样。

```text
python -X utf8 -m makesound.project_files index --project "<project>" --task "<stable-task-key>" --title "<任务名称>"
```

仅用户要求整理已有项目时，先核对哪些根目录 JSON 是 Agent 中间输入，再显式归档；不扫描并搬走全部 JSON、原稿或媒体。目标冲突或内部记录引用原路径时拒绝移动，不改写冻结记录。迁移映射和字节哈希写入工作目录；只移除已核对为空的旧导出目录，不删旧导出文件。

```text
python -X utf8 -m makesound.project_files organize --project "<project>" --task "<stable-task-key>" --title "<任务名称>" --input "<已核对的根目录输入.json>"
```

交付前核对：文件可读取；段号、角色和顺序与确认单一致；复用副本与来源一致；音频时长有效；同名 SRT 与音频对应且时间在范围内；合并停顿未重复；旧版本仍存在；交付说明准确反映成功与缺失范围。记录版本、句子与源 Job/音频的映射在 `.makesound` 中，不将密钥或敏感响应写入用户文档。未验证的实际听感单独说明。
