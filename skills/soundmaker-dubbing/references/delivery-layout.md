# 文件与交付规范

## 位置和命名

所有用户产物归当前项目，不写到 Skill 程序目录。默认使用 `配音/<任务名称>/`；用户明确指定已有目录时沿用。任务名从剧本标题或内容提炼为简短可读名称，同名的不同任务加编号区分，不覆盖原任务。清理文件名中的路径分隔符和 Windows 非法字符，不让用户文本成为任意路径。

```text
<当前项目>/
├─ 配音/
│  └─ 梦与潜意识/
│     ├─ 剧本.md
│     ├─ 配音演绎单_v01.md
│     ├─ 配音演绎单_v02.md
│     ├─ 交付说明.md
│     ├─ v01_初版/
│     └─ v02_阿哲换声/
│        ├─ 合并试听_第001-005段.wav
│        ├─ 合并试听_第001-005段.srt
│        └─ 分句/
│           ├─ 001_小林.wav
│           ├─ 001_小林.srt
│           ├─ 002_阿哲.wav
│           └─ 002_阿哲.srt
└─ .makesound/  内部状态、配置、绑定、计划、缓存和收据
```

使用原剧本的稳定段落编号，至少三位补零；全篇超过 999 段时统一增加位数。试听选了第 2、7、9 段，就保留 002、007、009，不能重新编号为 001、002、003。非连续范围的合并文件命名为 `角色试听_第002、007、009段.wav` 等，不能用连续范围误导。版本编号递增，名称说明变化；不要用 Job UUID、p_002 或“最终最终版”作为用户主要文件名。

## 格式和内容

- 剧本、演绎单和交付说明采用 UTF-8 Markdown。用户原始剧本文件保持不变；必要时生成可读副本，不把整理当作改写授权。
- 演绎单用中文角色名和绑定声音名，逐句展示实际参数。内部角色 ID、Job ID、计划哈希不放在正文开头；内部映射保存在 `.makesound`，需要排错时再引用。
- 默认音频 WAV，字幕同名 SRT；不为统一目录擅自重采样、改变声道或转为有损格式。额外 MP3 仅按用户需要本地导出。
- 分句音频保留完整语音及句内停顿，不截取、不限制十秒，不额外追加段间静音。若运行时源导出已有段后静音，仅根据可信的语音时长/导出元数据去除该追加部分，不能凭听感或猜测裁尾。
- 分句字幕从零计时；合并音频按原文顺序拼接，仅添加一次确认的段间停顿，合并字幕重算时间偏移。缺少真实字幕时明确标记未完成，不能编造时间或生成空字幕冒充成功。

## 版本和完成范围

每次修订只合成变化句子；新版本的 `分句/` 必须包含此次已完成范围内的全部可用片段和字幕，未修改的从已校验旧文件本地复制/复用，不再付费。用户拿一个版本目录即可剪辑，不必跨多个 Job 或 replacement-segments/original-segments 目录拼凑。

旧版音频、字幕、演绎单和收据一律保留。三个修订审核入口仍为：新合并音频、替换句、新版对应的旧句；旧句链接旧版本即可，不为提供入口重复建立含混的“原版”副本。

`交付说明.md` 明确列出当前可用版本及相对链接、对应演绎单、总段数、已完成段号、待生成或失败段号、修改内容和必要的格式/停顿说明。仅完成 6 段中的前 5 段时写“已完成第 001–005 段，第 006 段待生成”，不可标成全剧完成。首轮角色试听与完整对白交付也应明确区分。

后续批次可增补尚未占用的分句文件；生成新的合并范围文件并更新交付说明。任何已有文件若内容会改变，创建新版本，不覆盖旧交付。新合并或字幕失败时保留上一可用版本入口，并明确新版本尚未完成。

## 与现有运行时的衔接和验证

这是 Agent 的交付整理规则，不表示底层导出路径已变更。当前 `outputs/audio/<job_id>/` 仍是运行时源导出；不得直接移动或删除它或 `.makesound` 中的记录，以免破坏缓存、试听、恢复和追溯。通过本地复制与必要的本地合并建立上面的用户目录，聊天优先链接用户目录。已有项目不自动破坏性迁移，旧链接保持有效。

交付前核对：文件可读取；段号、角色和顺序与确认单一致；复用副本与来源一致；音频时长有效；同名 SRT 与音频对应且时间在范围内；合并停顿未重复；旧版本仍存在；交付说明准确反映成功与缺失范围。记录版本、句子与源 Job/音频的映射在 `.makesound` 中，不将密钥或敏感响应写入用户文档。未验证的实际听感单独说明。
