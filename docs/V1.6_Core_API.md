# V1.6 Core / Agent 2 接口说明

日期：2026-10-15。新的持久化后端可独立接入；现有 `studio_server.py` 和页面仍可保留 Mock。本文不要求修改旧 M1 CLI。

## 启动与信任边界

```powershell
python studio_v16_server.py --project "C:\明确的项目绝对路径" --fake
```

默认绑定 `127.0.0.1` 随机端口。启动输出一次 `{url, session_token, csrf_token, synthesis:"not_exposed"}`，由可信启动器传给页面，**不要把 token 存入项目 JSON、持久化 localStorage 或 URL 查询参数**。网页注入由 Agent 2/启动器实现，本轮没有改页面。

所有 API 请求带 `Authorization: Bearer <session_token>`。POST 还必须带相同服务的 `Origin`、`X-CSRF-Token: <csrf_token>` 和 `Content-Type: application/json`。Host 必须为当前端口的 localhost 或 127.0.0.1；Origin 必须与 Host 一致。不支持 API 查询参数，不支持跨域，不接受任意项目路径。POST 最大 1 MiB，拒绝重复 JSON 键和 NaN。

`--fake` 显式提供离线 Fake 模型；去掉时不会展示 Fake，但真实 Provider 合成仍不可用。不会自动读取火山生产配置路径。Python `StudioBackend(config_paths={...})` 允许可信启动器显式指定测试配置，不允许浏览器提交配置路径。

## HTTP 契约

| 方法 / 路径 | 请求 | 返回 |
|---|---|---|
| GET `/api/v16/providers` | 无 | `{providers, network_calls:0}`，非敏感模型和能力元数据 |
| GET `/api/providers` | 无 | 同上，兼容路由；新服务同样要求 token |
| GET `/api/v16/state` | 无 | `{preset, active_voice_ids, effective_defaults, previews, management}` |
| GET `/api/v16/questions/<question_id>` | 无 | `{question_id,job_id,roles,status,expires_at,answer}`；不暴露 Harness session ID |
| POST `/api/v16/voices/add` | `{name,category,source,revision}` | `{preset,project_voice_id}` |
| POST `/api/v16/voices/edit` | `{project_voice_id,patch,revision}` | `{preset}` |
| POST `/api/v16/defaults` | `{defaults:{general?,male?,female?},revision}` | `{preset}`，null 清空，省略槽位不改 |
| POST `/api/v16/settings` | `{settings:{...},revision}` | `{preset}`，项目导出设置 |
| GET `/api/v16/preview/<project_voice_id>` | 无 | `audio/wav`；缺失/损坏返回 404 |
| POST `/api/v16/answers` | `{question_id,assignments:{role_id:project_voice_id}}` | `{answer,resume_status:"saved_for_claim",agent_resumed:false}` |
| POST `/api/v16/complete` | `{}` | `{status:"management_saved",agent_resumed:false,network_calls:0}` |

没有 HTTP 合成、凭据写入、任意文件读取或 Harness 唤醒接口。不要把 complete 或 answers 的成功显示为“已恢复 Agent”。

可信启动器另将当前 question_id 传给页面；无 question_id 时使用主动管理模式。页面可读取上述 Question 接口展示必要角色，答案提交失败不会改写为已完成状态。

失败响应：`{error:<机器码>,message:<静态安全文案>}`。401 不使用；鉴权/Origin/CSRF 为 403，revision 冲突或回答已提交为 409，找不到为 404，字段/能力/模型错误通常为 400。UI 根据 error 显示适当说明；不要依赖 message 匹配逻辑。

所有项目写入需传最近读取的整数 revision。**后台成功提取试听也会增加 revision**，收到 `revision_conflict` 必须重新读取并让用户确认草稿，不能自动用新 revision 覆盖。

## 数据与控件映射

```json
{
  "source": {"provider":"fake","region":"test","model":"fake-v1","voice_id":"USER_VOICE_ID"},
  "patch": {"name":"教程旁白","category":"male","settings":{"speed":1.2,"pitch":2}}
}
```

以上只说明字段，不是单个 endpoint 的完整请求。category 为 `male|female|other`。source 四字段创建后不能编辑；修改来源应新建。Voice ID 原样保存，不做跨厂商复用或裁剪。名称采用 NFC，活动记录内唯一；同来源不同名称会生成不同 pv_id。

`patch` 只允许 `name/category/settings/deleted/acknowledge_unverified_settings`。软删除用 `{deleted:true}`，撤销用 `{deleted:false}`，保留默认原引用和试听文件；撤销名称冲突返回 `name_conflict`。不物理删除声音。改分类可能使性别默认失效，UI 保存前应提示；后端保留原引用，`effective_defaults` 则返回 null。

旧迁移声音如 `parameter_review_required=true`，新任务会报同名错误。原设置仍在 `legacy_settings`，用户明确同意暂不应用这些未验证参数后，才能提交 `{acknowledge_unverified_settings:true}`。这不是证明参数被真实厂商支持。

Provider 元数据包含 `models:[{id,name}], default_model, model_status, region, synthesis_status, capabilities, capability_status`。模型只取对应只读配置；default_model 不在 models 时标为 `invalid_default`，不选择替代模型。MiniMax/火山能力为空、真实合成标为 `provider_not_implemented`；只有 Fake 暴露经过本地契约验证的范围、step、unit、neutral、api_field。前端不能把 Fake 的范围复制给真实模型。

`previews[id]` 是 `{status,preview}`：status 为 `missing|unavailable|current|before_adjustment`。`before_adjustment` 对应“调整前试听”，仍可播放。metadata 含 sample_id、相对路径、实测时长、来源 job/chunk、固定来源、有效参数、signature 和音频摘要。**播放用 preview endpoint，不直接把磁盘路径作为 URL。** 使用带 Authorization 的 fetch 获取 Blob 再播放，避免把 token 放进音频 URL。

试听只复制已生成且单声的合格 WAV；不提供单独 TTS 试听或手动“使用最新”接口。没有合格样本时播放禁用。

## Harness / Python Core

```python
from pathlib import Path
from makesound.core_v16 import ProjectCore
from makesound.generation import Generation
from makesound.questions import Questions

core = ProjectCore(Path("C:/明确项目"))
questions = Questions(core)
# 信息不足时由可信 Harness 建题；job_id、Harness session ID 各自独立。
question = questions.create("job_pending", "harness_session_1", ["narrator"])
# 页面提交后，Harness 主动领取；wait 超时无需修改 Question TTL。
answer = questions.claim(question["question_id"], "harness_session_1")
engine = Generation(core)
snapshot = engine.freeze_from_answer(
    question["question_id"], "harness_session_1",
    [{"paragraph_id":"p1", "sentence_id":"s1", "role_id":"narrator", "text":"已确认原文", "pause_ms":300}],
    confirmed=True, authorized=True,
)
# 仅 Fake 能执行；真实 Provider 返回 provider_not_implemented。
result = engine.run(snapshot["job_id"], retry_failed=False)
```

没有待补问题的正常任务用 `Generation.freeze(segments, confirmed=True, authorized=True)`；segments 直接传 `project_voice_id`，或者用显式 `gender` 按默认规则解析。参数覆盖放在 segment.settings。默认解析顺序：明确 ID → 明确 gender 默认 → general → needs_question。明确声音无效会报错，不回退。角色名不参与性别判断。

输入为已结构化句子数组；paragraph_id 要连续，同一 sentence_id 不能重复。text 保留原始字符串，显式停顿由 pause_ms 提供；不自动解析文本中的停顿标记或舞台指令。Fake 专属 `fake_duration_seconds` 默认 6 秒，只是离线时序控制，不是基于字数猜字幕。Job 默认 paragraph、句级字幕、WAV；其他编码返回 `export_not_implemented`。

`run` 只重用已冻结配置。已提交回答也保存 resolved 配置，因此回答后编辑/删除声音不破坏当前任务。`freeze_from_answer` 要求答案已被正确会话领取，不允许额外覆盖答案绑定，使用原 Question 的 job_id，拒绝覆盖现有 snapshot。单次领取状态不会伪称网页自动唤醒 Agent。

## 显式迁移 / 回滚

调用 `core.migrate(region=..., model=..., assets=...)`，将旧 1.1/1.2 导出到独立 V1.6 文件；旧文件在原位不变。只有 region=configured/1.1 才需要显式 region；model 缺失需明确传入；global_asset 引用需传可信资产映射。失败不会静默猜模型、区域或丢失引用。

备份先保存为 `.makesound/preset.pre-v16-<hash>.json`；未知非敏感数据完整保留到 compatibility.original，旧别名到稳定 ID 的映射保留到 compatibility.aliases。旧数据含敏感字段时会拒绝迁移，需先清理，不能将凭据一并复制到项目数据。旧参数不被虚假校验为新能力，必须显式复核。

`core.rollback_migration(revision=0)` 仅在迁移后尚未写入新业务数据、旧文件内容未变时允许，将 V1.6 文件移到同目录归档，旧文件始终保持原样。revision 非 0 时返回 rollback_conflict，避免丢失新数据。
