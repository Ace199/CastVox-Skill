## 1. 产品定位与原则

Voice Studio 是 MakeSoundSkill 的**可视化声音选择、配置与回答界面**，不要求用户每次生成语音都打开。Agent 首先理解当前对话、识别需要发声的角色和已有项目声音，能自动决策的部分无需用户重复选择；只有需要浏览、试听或补全配置时打开 Studio。

两种入口：

1. **Agent 请求入口**：携带 project_id / job_id / question_id / 本次识别的角色需求、意图标签、已明确的分配；“完成设置”只提交当前问题的回答，再由 Agent / CLI 继续。
2. **主动管理入口**：用户打开工作台管理项目声音、默认和参数；没有当前 Job 时，不呈现含义不清的“继续生成”操作。可单独保存资产和默认。

设计不变量：已试听音频是生成结果，不是新的 Voice ID；只有复刻/文本设计音色才可能创建新的 MiniMax Voice ID。参数与音色身份分离；Job Snapshot 冻结实际 provider、region、voice_id 和参数；默认不能被本次临时修改静默覆盖。

## 2. 单屏整体信息架构

```text
┌──────────────────────────── 左侧工作区 ─────────────────────────────┬──────── 右侧操作面板 ────────┐
│ 项目已有人格 / 项目声音库                                          │ Tabs: 基础设置 / 探索更多 / 音色生成 │
│   男声 [音色][音色][...                                ]           │ 当前对象 / 上下文提示          │
│   女声 [音色][音色][...                                ]           │ 设置 / 试听 / 保存操作         │
│   ↑ 男/女行使用同一个水平滚动容器                                   │                                │
│ 需求： [默认声音] │ [1 主角A][2 主角B][3 旁白] ...（独立横向滚动）     │                                │
│ [完成设置 / 提交回答]                                              │                                │
├───────────────────────────────────────────────────────────────────┤                                │
│ 声音池：来源、标签、搜索、候选卡片、试听入口                         │                                │
│ [卡片][卡片][卡片] ...                                              │                                │
└───────────────────────────────────────────────────────────────────┴────────────────────────────────┘
```

功能区是组织单位而非四个独立页面。左侧上方项目声音库与下方声音池是不同对象；右侧展示**当前上下文所选对象**的设置。

### 2.1 项目声音库（上方）

- 展示当前项目已保存的命名声音引用（Project Voice Alias）及其可用配置；按**男声 / 女声**两行排列。来源没有可靠分类时进入「未分类」兼容分组，**不可仅从名称推断声别**。
- 男、女两行**同一个水平滚动容器，共享水平滚动偏移**；行标题固定。允许声音很多时横向滚动；每张卡固定可预测的尺寸。
- “下方添加更多”是**纯提示文本**，不是跳转按钮或操作入口。
- 声音卡支持试听。Hover / keyboard focus：右侧**设置图标滑出或浮现**，声音名称向左让位；**卡片外框不动、试听按钮位置不动、相邻卡片不被挤动**。点击设置图标才打开项目声音配置详情；普通点击用于当前选中的任务角色直接分配声音（要有清楚反馈）。
- 在触屏环境无法 Hover，应提供常驻或可发现的设置入口。
- 同一个声音可分配给多个需求角色，角色级参数可以不同。修改项目声音本身须显式保存并处理 revision 冲突。

### 2.2 当前需求 / 角色分配区

- Agent 从**此次对话 / 已确认稿件**识别角色数量、名称及约束，传入当前 Job；用户不应再手动从头录入所有角色。
- 左侧固定一个「默认声音」按钮；其右用竖直分隔线与需求角色隔开。这里的**默认声音明确指项目的持久默认声音**（已确认 B），不是本次任务临时 fallback。选定它并保存后更改项目持久默认，不能仅靠点击就写盘。
- 分隔线右侧是一条**独立横向滚动的需求角色列表**，与男/女声音库滚动互不影响；默认声音按钮固定不滚动。大量角色时仍可找到当前选中项，可自动 scroll into view。
- 当前激活的默认/角色按钮采用**特殊可识别描边**；区分「当前选中」与「已成功分配」。角色展示绑定的音色名称与完成状态，支持重选。已明确指定的项目声音由 Agent 预绑定，减少重复操作。
- 选中角色后再点上方已有声音，立即绑定到此角色并刷新卡片；角色仍可重新绑定，自动聚焦下一个待分配角色可作为 SHOULD（不可造成意外切换）。
- 角色的 Task Voice Selection 是当前 Job 的映射，而项目声音库是持久复用的声音集合。不得混写作用域。
- 当进入时没有当前 Job，角色区域可空态 / 隐藏，仍允许管理项目默认声音。

### 2.3 声音池（下方）

- 来源过滤：MiniMax 官方音色 / 我的声音（已创建、复刻音色）等；文字/标签筛选（如青年、女声）仅使用可靠的元数据来源，来源不明应标注“未确认”。
- 可以搜索、浏览候选、试听。点击声音池卡片会在右侧「探索更多」显示该声音（不直接把候选加入项目）。
- 官方 `get_voice` 文档提供声音列表，但 M0 未确认查询响应包含官方试听音频 URL。默认按需合成并本地缓存试听，**未缓存时用户明确点击付费试听**；不能首次打开批量为所有官方音色合成。
- 缓存按照 provider / region / model / voice_id / 试听文本 / 有效声音与文本参数区分。不同参数不能误用旧音频。

## 3. 右侧操作面板

右侧始终保持工作区的详情位置；三个 Tab：**基础设置 / 探索更多 / 音色生成**。

- **默认打开「探索更多」**。无选中声音时，浏览候选的入口仍可用；进入需明确声音对象的详情子面板但目标为空时，显示「请选择声音」。
- 从上方项目音色卡的**设置按钮**进入：选定对应声音，自动切到「基础设置」。
- 从下方声音池的候选卡进入：选定候选，自动切到「探索更多」。
- 点击角色按钮：选中分配目标，右侧展示该角色已绑定声音（如有）及参数；没有绑定时提示选择项目库/声音池候选，而不是伪造默认绑定。
- 点击「默认声音」：将编辑目标切到项目持久默认；应用新的默认前显示修改预览与**确认保存**。
- 两个设置 Tab **共享同一份未提交编辑状态**，切换不清空已改参数，试听缓存及“参数已变化”状态一致。

### 3.1 基础设置（已有声音参数调整）

**不展示音色选择、不展示音调 Pitch 调节。** 当前声音仅作为顶部只读上下文。

保留：

- 情绪 Emotion（auto、开心、悲伤、愤怒等）：受所选模型能力矩阵约束，不支持的选项可见但禁用；auto 转换为省略 MiniMax emotion 字段。
- 语速 Speed。
- 音量 Volume。
- LaTeX 公式朗读：布尔开关。
- 中英文文本规范化：布尔开关。
- **试听文本**：Agent 从当前已确认的脚本中选取一条较长、完整、可朗读的句子；允许用户编辑；无稿件时提供不包含隐私的本地样本文本。勿擅自改写原脚本。
- **生成试听**：用户主动点击才可能调用付费 API；生成成功后显示真实可播放音频、时长及是否匹配当前参数。缓存命中只本地播放。

若试听后继续调整设置，旧音频允许播放，但标明“旧参数试听”，不能作为当前设置已试听的凭据。

### 3.2 探索更多

**探索更多 = 基础设置全部功能 + 模型选择 + 音色选择。** 不制作两套不同的试听/保存逻辑；只是多开放两个选项。

- 模型切换要重算情绪兼容性、输出支持及费用提示，不得静默替换不兼容参数。
- 音色可以从官方列表、个人音色及当前项目已有声音中选择（去重规则由后端实现定义）。
- 初始进入时默认该 Tab；用户选定声音后可调整参数、试听。

### 3.3 音色生成（暂不展开 UI）

- Tab 占位即可，**不在本轮实现文本设计音色和复刻的 UI**。
- 产品方向：新创建音色默认归属当前项目，包括创建产物与 Voice ID 的项目管理关系；这与 M1 的全局资产注册机制存在数据层差异，留在“待迁移决策”，不得把源码/全局目录直接删掉。

## 4. 试听结果与两个核心动作

试听使用当前具体 Voice ID + 模型 + 情绪/语速/音量 + 文本开关 + 试听文本合成；**试听 MP3 只是样本音频，不是新的音色资产**。

成功试听且编辑参数与音频一致后，展示：

1. **加入角色池**：把选中声音及当前参数配置赋给当前选中角色，仅对此 Job 有效，不写项目持久音色库。
2. **加入项目库**：输入当前项目内唯一名称，保存音色引用及相应声音参数；在存在当前选中角色时**同时加入角色池**。重名须提示并经 revision 安全确认才能重绑定。

如果选中的目标是「默认声音」，不能将其当成普通任务角色：提供明确的「保存为项目默认声音」确认动作，**允许不添加命名项目音色直接保存默认 Voice ID**。默认保存和项目别名添加是独立动作。

主动管理入口且无当前角色时，「加入项目库」仍然允许单独保存；「加入角色池」应禁用/解释当前没有可用的任务目标。未经试听的项目现有声音直接绑定角色，原本可行；**不要把“必须试听”强制加到所有已有声音分配路径**。新增/调整参数后的“试听→加入”是主要操作路径，而不是唯一合法绑定路径。

## 5. 完成设置与提交边界

- Agent 请求模式：提交当前 Job 的角色绑定、显式保存意图及必要参数，传回 `question_id/job_id` 对应的 Answer；阻止未分配且无可接受回退的必需角色继续。
- 本地管理模式：仅提供保存当前项目资产/默认设置的动作，不向不存在的 Job “继续”。
- `studio wait` 超时≠问题 TTL 过期，已提交回答持久可领取；若 Agent 已结束，只显示“已提交，待继续”，不可声称已自动恢复。
- 保存和真实收费 TTS 合成是不同授权动作。试玩/生成试听可能收费，需明确提示；未操作时不能自动收费生成。
- 多声音角色分配最终必须冻结为实际 `provider + region + voice_id + 有效参数`，以供下一阶段 Chunk Planner 使用，不能只在 Job Snapshot 中保留别名。

## 6. 状态与异常矩阵（Wireframe MUST 演示）

| 场景 | 应有界面行为 |
|---|---|
| 当前无项目声音 | 项目声音库空态，下方声音池可浏览与补充 |
| 当前无任务角色 | 主动管理模式；隐藏或禁用“加入角色池”，默认设置仍可管理 |
| 已有 N 个角色 | 需求区独立横向滚动，选中目标始终可定位 |
| 项目声音很多 | 男女两行共用水平滚动；标签保持固定 |
| Hover 音色卡 | 固定尺寸，设置图标出现，名称左移，试听按钮位置不动 |
| 当前未选声音 | 默认探索更多；需要声音的详情显示「请选择声音」 |
| 选定声音后改参数 | 试听标识失效；保存操作明确新参数是否已经试听 |
| 试听 API 失败 / 可能收费 | 明确错误/风险；保留编辑内容；不得自动重发不明账单请求 |
| 项目别名重名 | 需二次确认，revision 校验；不得静默覆盖 |
| 改默认声音 | 确认后持久化，旧任务快照不变 |
| 某角色音色未定 | 需求项高亮待补，不能伪装完成 |
| 网页只用于管理 | 不显示无意义“完成并继续生成” |

## 7. 阶段交付与验收

本轮（UI 设计阶段）交付：

- **一个自包含、可点击的 HTML 工作台线框图**；不再将首次配置与缺失别名作为互不连通的两个主页面。
- 左侧三区域 + 右侧三个 Tab；至少模拟「已有多个角色 / 没有项目音色 / 无角色的管理模式」。
- 可见模拟试听、按钮反馈、水平滑动、项目默认保存确认及分配结果汇总。
- 标注每个操作是 Mock、未来本地 CLI、还是将来可能收费的 API；不调用真实 MiniMax、不修改真实 M1 配置。
- 窄屏及键盘可达性；不得只有 hover 才能执行设置。

下一阶段：结合视觉参考文档制作一屏高保真探索；设计评审后才拆解 M3 的真实 UI/API 接线任务。M2（音频、字幕和缓存）仍按 V1.2 规划独立进行。

## 8. 明确尚未解决的产品/工程边界

1. 新创建声音的**项目归属**如何映射到现有全局 Voice Asset Registry；项目删除/搬移、跨项目复用和样本存储/清理策略，需要额外 Schema 设计与迁移方案。
2. 项目声音按男/女两行，遇到官方 metadata 无性别或分类证据时，UI 可增加「未分类」；具体标签来源优先级待实现落地。
3. `默认声音` 保存确认后是否同步影响右侧角色的本次临时配置：原则上不覆盖已经明确分配的角色，未分配角色的 fallback 按任务创建 Snapshot 时确定。
4. 各 MiniMax 模型可用情绪、试听响应、文本开关的真实 API 字段和费用以 Capability Matrix 更新和受控测试为准，勿在 Mock 中暗示验证通过。
5. 本文 UI 结构是对 V1.2 §5.3 三个一级页面的**明确替代**；其他 V1.2 原有非 UI 需求仍有效。
