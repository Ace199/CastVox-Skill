# MakeSoundSkill — 产品需求文档 PRD V1.6

> 版本：V1.6 · 2026-10-15  
> 状态：本轮已确认的产品与交互开发基线；具体 Provider 能力、旧数据迁移和 Harness 联调仍待验证。  
> 范围：Windows 本地优先，Codex / Claude Code；Voice Studio 使用 HTML/CSS/原生 JavaScript，Python Core 复用 M1。  
> 上游：PRD V1.5、Voice Studio Visual Direction V1 与本轮确认。本文完整描述当前目标；冲突时以本文为准。  
> 首个真实合成 Provider：MiniMax。火山引擎本阶段仅配置与引导，不承诺真实合成。

## 0. 产品定位与本版结论

MakeSoundSkill 让 Agent 复用项目中已经确定的声音，完成口播理解、角色分配、演绎编排、分段合成、字幕、导出和恢复。用户在厂商平台试听或创建声音并复制 ID；Studio 负责项目声音配置、管理及任务补全。

声音卡代表一份具有稳定内部身份的项目声音。添加时固定厂商、区域、模型与 Voice ID；之后可修改名称、分类、语速和声调。右侧表单切换厂商、模型或 ID，只影响正在添加的声音，不改变已有声音卡。

### 0.1 V1.6 主要变化

| 项目 | 本版决定 |
|---|---|
| 右侧面板 | 三个 Tab：添加项目声音 / 声音设置 / More Tools |
| 声音编辑 | 名称、分类、语速、声调可改；厂商、区域、模型、Voice ID 只读 |
| 默认设置 | 默认声音、默认男声、默认女声；两行展示，全部可留空 |
| 项目试听 | 不爬取官网、不额外合成；复用首次符合条件的成功生成片段 |
| 参数调整后的试听 | 旧样本仍可播放，标注“调整前试听”；后续符合条件的新样本替换 |
| 删除 | 卡片连续悬浮 2 秒显示 ×；通过 deleted 字段软删除，保留记录、引用和试听 |
| 任务隔离 | 已冻结任务沿用快照；新任务使用新设置，并排除已删除声音 |

### 0.2 保留与排除

保留多声音任务、项目预设、Provider 配置读取、Agent 自动演绎、音频/SRT、缓存、续跑、Question/Answer 恢复链路。

本阶段不实现官网音色爬取、官方声音池、声音克隆、文本设计音色、单独收费生成试听、轨道编辑或复杂角色池。More Tools 只占位。情绪、停顿与语气词由 Agent 根据语义和用户指示处理，不增加逐项编辑面板。

## 1. 用户流程

### 1.1 首次设置

1. 用户确认口播稿并请求配音。
2. Core 解析指定声音、默认设置和当前角色；足够则直接进入任务准备。
3. 信息不足时创建 question_id / job_id，打开本地 Studio。
4. 用户在右侧选择厂商、已配置模型，填写 ID、名称与分类，添加项目声音。
5. 用户按需配置默认声音，并为必要角色分配声音。
6. 点击“完成设置”，提交结构化回答；由等待中的 Harness 领取并继续。提交本身不直接发起收费 TTS。
7. 真实生成成功后，为对应声音保存首个符合规则的本地试听片段。

### 1.2 后续使用

Agent 优先使用本次明确指定或分配的声音，否则按默认规则解析。创建 Job 时冻结完整有效配置与执行参数。已有完整配置时无需打开 Studio。

### 1.3 主动管理

用户主动打开 Studio 可添加、编辑、设置默认或删除声音。没有等待中的 Question 时，完成操作只表示管理完成，不显示“已恢复 Agent”等虚假状态，也不启动 TTS。

## 2. 单屏布局

桌面左侧约 55–62%，右侧约 38–45%；窄屏上下排列，不出现页面整体水平溢出。

### 2.1 左侧项目已有声音

- 展示项目名称与可信项目位置。
- 男声、女声、其他三行，分类标签固定，声音卡共用一个水平滚动位置。
- 紧凑横向短卡：头像、固定位置播放按钮、名称、设置入口、延迟出现的删除按钮。
- 分类由用户选择，不根据名称或 ID 猜测性别。
- 卡片主体用于给当前选中的任务角色分配声音；播放、设置、删除属于独立点击区域。
- “在右侧添加更多项目声音”为轻量提示，不恢复下方官方声音池。

### 2.2 左侧默认设置：独立两行

第一行：默认声音。第二行：默认男声、默认女声。

三个位置均为可选选择器，支持“不设置”和清空；候选来自未删除的项目声音。男声/女声默认候选按用户分类筛选，通用默认允许所有分类。名称旁可有试听入口，但默认设置不复制声音记录。

默认设置属于项目持久偏好，与当前任务角色分配独立。更换或清空需显式保存并确认，不随角色点击隐式修改，也不要求全部填满。

### 2.3 左侧当前需求

- Agent 提供本任务的角色按钮；用户选择角色，再点击声音卡完成分配。
- 需求按钮独立横向滚动，与项目声音列表互不影响。
- 角色选中与已分配是两个状态；文字、序号、勾选同时表达，不单靠颜色。
- 默认设置不混入任务角色滚动区。
- 必要项未满足时“完成设置”禁用，说明缺少的角色或配置；可选默认留空不阻止提交。

### 2.4 右侧三个 Tab

| Tab | 进入方式与内容 |
|---|---|
| 添加项目声音 | 默认激活；厂商、模型、官网引导、名称、ID、分类、添加动作 |
| 声音设置 | 点击卡片设置入口自动载入；名称、分类、语速、声调、只读来源、试听与保存 |
| More Tools | 仅占位，不伪装有业务能力 |

切换 Tab 保留草稿；切换所编辑声音时，若有未保存修改，提示保存或放弃。没有选中编辑对象时显示“点击项目声音卡上的设置图标进行编辑”。

## 3. 添加项目声音

| 字段 | 规则 |
|---|---|
| 厂商 | MiniMax / 火山引擎；不同厂商使用各自引导和字段描述 |
| 模型 | 从对应厂商 config.json 的 models 经后端脱敏读取，不在前端硬编码 |
| 项目声音名称 | 必填，活动声音中规范化后唯一 |
| Voice ID / 厂商音色标识 | 必填，保留原始字符串，不能跨厂商复用草稿值 |
| 分类 | 男声 / 女声 / 其他，用户明确选择 |
| 语速、声调 | 添加时使用对应模型的已验证中性默认；添加后在声音设置调整 |

切换厂商重新加载模型和引导；各厂商草稿分别保留，不能将旧模型或 ID 视作新厂商有效配置。模型缺失时明确显示“该厂商尚未配置可选模型”，不静默回退。

MiniMax 引导入口沿用 V1.5 的 https://www.minimax.cn/audio 。火山官方入口和字段契约仍需核实，未核实时不编造链接；显式标注“仅保存配置，暂不可由本 Skill 生成”。

“添加到项目库”校验并原子保存，成功后卡片进入左侧对应分类。不因新增同名声音覆盖旧记录。新声音可提供未勾选的“同时设为项目默认”选项；用户明确选择才保存默认。

同一来源允许以不同名称保存多张卡，用于不同语速/声调版本。内部 ID 分别生成，不按别名或厂商 ID 合并。

## 4. 声音设置

### 4.1 可编辑范围

| 项目 | 是否可编辑 | 保存影响 |
|---|---|---|
| 名称 | 是 | 仅显示名称；内部引用不变 |
| 分类 | 是 | 切换展示分组；不改变来源身份 |
| 语速 | 是，能力允许时 | 新任务执行参数改变，试听可能标旧 |
| 声调（Pitch） | 是，能力允许时 | 新任务执行参数改变，试听可能标旧 |
| 厂商、区域、模型、Voice ID | 否，只读 | 需要其他来源时新建声音卡 |

语速与声调提供滑块、数值输入和恢复默认。范围、步长、单位、中性值与 API 映射由 Provider/模型能力描述器提供；不假设厂商共用相同单位。不支持或尚未验证时禁用并说明，不默默丢弃用户设置。声调与情绪不是同一参数。

底部提供“取消”“保存修改”。草稿不影响播放、角色或执行，保存成功后才更新项目记录。名称/分类修改不让试听变旧；有效语速/声调变化才重新比对试听参数。

若分类改变导致男声/女声默认槽位不再匹配，保存前提示该默认将显示未设置；保留旧引用数据，不自动替换其他声音。已有明确任务引用不因展示分类变化自动换声音。

### 4.2 参数解析和快照

优先级：用户本次明确参数覆盖 → 项目声音保存的语速/声调 → 模型中性默认。Agent 自动编排不能无依据覆盖用户显式设置。

每个新 Job 保存内部声音 ID、来源、有效参数及能力校验结果。已冻结 Job 与恢复任务使用原快照，不因后来编辑、删除或默认变化重新解析。

## 5. 默认声音与任务声音解析

### 5.1 解析顺序

1. 用户本次明确指定、或 Studio 对当前角色的明确分配。
2. 需求明确为男声/女声时，使用相应默认男声/默认女声。
3. 使用通用默认声音。
4. 仍缺少则提问，不猜测，不从卡片中随机选择。

只有用户/任务明确提供声音性别需求时才使用性别默认；不能凭角色名猜。默认槽位留空属于合法配置。明确指定的声音不可用时应报可修复问题，不用默认静默替换；配置存在但 Provider 不可用也不能静默跨厂商回退。

### 5.2 默认引用

新设置保存内部 project_voice_id，不复制配置。指向 deleted 声音、缺失记录或不匹配分类的槽位在 UI 显示“未设置”，解析时当作未设置；原始引用可保留，直到用户显式改写。

语速/声调编辑后，之后通过默认引用创建的新任务使用最新保存参数。历史及已冻结任务不受影响。

## 6. 本地试听缓存

### 6.1 获取来源

不在网站打开时爬取官网，不启动后台 TTS，不为播放按钮额外计费。只复用项目真实任务已经成功生成的分段音频。

对每个项目声音及其有效试听参数，按文稿分段顺序检查成功片段，选择第一个实测时长在 5–10 秒（含边界）的片段。必须为单一声音、同一来源及同一有效语速/声调；不拼接不同角色，也不把多个声音的最终混音用作试听。若多个 Chunk 并发完成，应按文稿顺序选择，不按网络完成时间抢占。

复制为独立项目文件；不硬截长片段，不额外制造短句。没有符合条件的片段则保留原样，等待后续成功任务补齐。试听失败不影响主任务成功。

### 6.2 保存位置与元数据

建议位置：`<project>/.makesound/previews/<project_voice_id>/<sample_id>.mp3`。

文件扩展名与真实编码一致；可复制原有可播放格式，需转码时仅做本地处理。记录样本 ID、相对路径、实测时长、来源 job/chunk、来源身份、有效语速/声调及参数签名。不可只保存对导出文件的脆弱引用。

同一声音卡有独立试听记录，不因添加表单切换配置而改变。不在 V1 自动跨卡共享样本。

### 6.3 播放状态

| 状态 | 表现 |
|---|---|
| 暂无样本 | 播放禁用，提示“首次生成符合条件的配音片段后可试听” |
| 当前参数样本有效 | 可播放、暂停；点击另一声音时停止前一个 |
| 调整后仍为旧参数样本 | 继续可播，显示“调整前试听” |
| 文件缺失/损坏 | 不播放，提示“试听文件不可用”；后续任务补齐 |
| 正在保存新样本 | 保持旧样本可用，写入成功后原子切换 |

修改名称/分类不改变试听签名。改变语速/声调后，旧样本保留；下一次新参数生成首个符合条件的片段时替换。若参数改回与样本一致，取消“调整前试听”标记。

只允许与当前保存参数一致的任务结果更新当前试听；旧任务晚完成不能覆盖新参数试听。若任务级显式参数与卡片保存参数不同，也不将它标作当前卡片参数样本。普通后续生成不反复覆盖已有有效样本；设置页可提供“使用最新配音更新试听”，只从已有合格片段中更新，不调用 API。

## 7. 悬浮删除与软删除

### 7.1 卡片交互

- 鼠标连续停留在同一张卡片上 2 秒后，预留的右上角显示 ×。
- 移出整个卡片含 × 区域时隐藏并重置计时；移动到 × 不隐藏。
- 卡片主体、播放、设置、删除互不触发；× 出现不挤动名称、播放按钮或卡片尺寸。
- 设置入口与 × 分开布局，先按右侧不同位置做原型验证。
- 键盘聚焦可访问删除入口；触屏通过设置菜单删除，不依赖 hover。

### 7.2 删除语义

删除只将记录设为 `deleted: true`，不物理删除 JSON 记录、默认/角色引用、试听文件或导出音频，不调用厂商删除 API。正常项目库与新分配候选隐藏 deleted 记录，V1 不新增回收站面板。

| 对象 | 删除后的处理 |
|---|---|
| 未被使用声音 | 直接隐藏，提供短暂撤销 |
| 当前开放任务中的明确分配 | 保留 ID 和已解析配置，角色可继续显示“已分配（已从项目库移除）”；允许重新选择 |
| 已冻结/执行中/历史 Job | 完全沿用快照 |
| 项目默认槽位 | 原引用保留，UI 显示未设置；后续自动解析跳过 |
| 未来任务候选 | 不自动选用，不作为新的可选分配 |

有引用时删除前用简短确认说明“从项目库隐藏；已有任务保留，后续默认不再使用”。不提示会清空已有角色。新请求明确提到已删除声音时提示用户选择活动声音或恢复，而非悄悄继续。

撤销恢复 `deleted: false`。未被用户改写的默认引用可恢复显示；不得覆盖删除后用户手动选择的新默认。软删除名称保留内部历史身份，但不阻止以同名创建新记录；若撤销时活动名称冲突，提示改名后恢复，不能覆盖新声音。

## 8. 数据与持久化

### 8.1 分层

| 层级 | 内容与权限 |
|---|---|
| Provider config.json | 凭据、区域、Base URL、models 与能力元数据；MakeSound 只读 |
| Project Preset | 内部声音 ID、名称、分类、固定来源、可编辑参数、deleted、试听、默认引用；原子写入、revision 校验 |
| 当前 Task Assignment | 任务角色到声音 ID 的明确分配；不静默写成项目默认 |
| Job Snapshot | 任务创建时的已解析来源与参数；冻结后不重算 |

### 8.2 目标结构示例

以下为语义示意，非声称 M1 已支持的新强制格式。模型名与数值只是占位，不代表账号权限、实际模型或统一 API 参数范围。

### 8.3 兼容策略

先审查 M1 现有结构，保留既有离线回归结果。新字段默认：deleted=false、preview=null，语速/声调依模型中性值兼容。按名称存储的旧记录需稳定 ID 映射，不让重命名破坏旧引用。

旧版直接引用型默认声音不能丢失；迁移时复用精确匹配的项目声音，否则创建可见的兼容声音记录并保留来源。执行显式迁移、备份、版本检查和回滚验证，不无提示覆盖旧 Schema。保留旧数据的未知字段；不重写历史 Job。

## 9. Provider 配置与能力

MiniMax 路径沿用 `Path.home() / .config/minimax/config.json`；火山配置路径由部署规范确定。前端只能读取后端提供的非敏感元数据，不能直接 fetch 原始凭据文件。

- models 必须来自相应配置；default_model 必须属于 models，错误时提示修复。
- 配置默认模型变化不改变已有声音固定模型。
- 保存配置不等于模型可用、账号开通或已经实现真实 Provider。
- 项目声音来源固定不代表凭据永远可用；每次执行校验对应区域、Base URL、模型能力和权限，不跨区试 Key、不静默换模型。
- speed/pitch 的能力可由经验证的 Adapter 描述器提供；不要求用户在凭据文件中维护未经证实的范围。
- 火山 Adapter 未实现时明确返回 provider_not_implemented，不回退 MiniMax。
- doctor 只输出脱敏诊断，不在浏览器、项目 JSON、Snapshot 或日志暴露 API Key。

## 10. Agent 演绎、生成与恢复

### 10.1 原稿与演绎

保留 Document → Paragraph → Sentence 结构、术语、版本号与显式停顿标记。明确不朗读的镜头备注剔除并保留审计。Agent 按语义规划角色、情绪、停顿与必要语气词，不擅自增加笑声、咳嗽或改写已确认原文；用户明确要求优先。

### 10.2 执行

Core 校验 Manifest 与模型能力，将不同厂商/区域/模型/Voice ID/有效语速声调或不可混合演绎配置分为独立 Chunk。MiniMax 私有 token 由 Adapter 编码，不直接透传其他厂商。自动情绪在适用 Provider 中映射为省略参数。

输出 whole / paragraph / sentence，默认 paragraph；字幕默认开启、句级 SRT，依可靠供应商时间信息与实测最终音频时长，不按字数猜时间。保留成功 Chunk、缓存与失败信息；不为凑试听时长改变生产分段逻辑。

收费请求须具备确认文本、有效配置与用户任务授权。计费状态不明时不盲重试。试听提取完全在成功音频之后执行，独立失败，不触发追加收费。

### 10.3 Studio 与 Harness

本地服务只监听回环、随机端口、严格令牌/Origin/CSRF与路径校验；不向远程 Harness 宣称不可达的 localhost 可用。question_id / answer_id / job_id 与 Harness Session ID 分开。

“完成设置”校验必要角色与配置，记录不可变结构化回答，再请求恢复；等待中 Agent 领取继续，已退出时持久保存，供用户再次“继续任务”领取。wait 超时不等于 Question TTL 到期。无真实桥接确认不声称网页自动唤醒 Agent。

项目保存、默认保存、回答提交、真实合成是不同动作；已保存但未提交的管理更改不伪装任务已恢复。

## 11. 视觉基线

沿用 Cel Shading × Bauhaus/Mondrian × 克制 Neo-Brutalist：近白大面积留白、墨黑清晰描边、纯色、方角和少量硬偏移阴影；钴蓝体现选中，明黄强调主要动作，少量红色提示。

强化编辑式排版、网格与卡片秩序，避免普通系统表单感；标题不挤占工作区。不使用渐变、玻璃、霓虹、软浮雕、大插画或 WEFT 品牌。头像色不与性别强绑定。

本轮生成图是视觉参考，尚未包含本版新增的默认两行和声音设置 Tab；以本文交互为准。Visual Direction V1 中旧“探索更多/基础设置/声音池/收费试听”条款不再适用。

键盘焦点明显、点击区域明确；禁用与错误有文字说明。支持 reduced motion。悬浮按钮出现不改变布局，试听旧参数标记保持轻量。

- [ ] 表单换模型、厂商、ID 不影响任何已有卡片。
- [ ] speed/pitch 范围来自验证能力；不支持项禁用，后端再次验证。
